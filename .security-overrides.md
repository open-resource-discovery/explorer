# Security Overrides

Overrides in root `package.json` that force safe versions of transitive dependencies.
Each entry is removed automatically by the dep-sweep skill when `npm audit` is clean for that package.

## @ai-sdk/provider-utils (transitive via ai, @ai-sdk/gateway, @ai-sdk/vue)

- **Override**: `"@ai-sdk/provider-utils": "4.0.51"`
- **CVE**: CVE-2026-8769
- **GHSA**: GHSA-866g-f22w-33x8
- **Severity**: low
- **Summary**: Uncontrolled Resource Consumption in `@ai-sdk/provider-utils`; fixed in 4.0.33
- **Dependabot alert**: #6
- **Added**: 2026-09-09, bumped 4.0.50 → 4.0.51 on 2026-09-21 (Renovate PR #34)
- **Note**: `ai`/`@ai-sdk/gateway`/`@ai-sdk/vue` pin provider-utils to `4.0.5`. Pinned to `4.0.51` (head of the `ai-v6` / 4.0.x line, matching `ai@6.x`); clears the full low-severity cascade through `@ai-sdk/gateway`, `@ai-sdk/vue`, `ai`, and the `@scalar/*` → `@open-resource-discovery/metadata-renderer` chain. Renovate PR #38 proposes a `v5.0.45` major here — deliberately NOT taken: forcing the transitive to a major the parents were not built against risks runtime breakage in the scalar/api-reference chain that unit tests do not exercise. Left open for a maintainer to evaluate separately.
- **Remove when**: `npm audit` reports no advisories for `@ai-sdk/provider-utils` (when the `ai`/`@ai-sdk/*` packages upgrade their pinned provider-utils past 4.0.32)

## js-yaml (transitive via @asyncapi/parser)

- **Override**: `"js-yaml": "4.3.2"`
- **CVE**: CVE-2026-84375
- **GHSA**: GHSA-2883-xcg3-v3hh
- **Severity**: high
- **Summary**: `js-yaml`: `maxTotalMergeKeys` does not limit CPU use for empty merge sources; fixed in 4.3.2
- **Dependabot alert**: #7
- **Added**: 2026-09-21
- **Note**: `@asyncapi/parser` pins `js-yaml@4.3.1` (vulnerable range `>= 4.0.0, < 4.3.2`). Pinned to the exact first patched 4.x release `4.3.2` — an open `>=4.3.2` floor lets npm cross into `js-yaml@5.x`, a major with breaking API changes `@asyncapi/parser` was not built against. Only lock file affected is the root `package-lock.json`; `app/` and `auth-proxy/` do not depend on js-yaml.
- **Remove when**: `npm audit` reports no advisories for `js-yaml` (when `@asyncapi/parser` bumps its pinned js-yaml to ≥ 4.3.2)

## undici (transitive via isomorphic-dompurify)

- **Override**: `"undici@7": "7.29.1"`
- **CVE**: CVE-2026-19534, CVE-2026-84961, CVE-2026-18149, CVE-2026-84890, CVE-2026-84933, CVE-2026-85014, CVE-2026-85024, CVE-2026-18540, CVE-2026-84947, CVE-2026-85008
- **GHSA**: GHSA-rfgv-xxqx-mfg5 and 9 others (see alerts below)
- **Severity**: high (plus medium/low)
- **Summary**: Multiple `undici` DoS / TLS-bypass / response-splitting advisories; all fixed in 7.29.1
- **Dependabot alerts**: #15, #11 (high); #17, #14, #13, #9, #8 (medium); #16, #12, #10 (low)
- **Added**: 2026-10-02
- **Note**: Scoped to the 7.x line only (`undici@7`), which pins `isomorphic-dompurify`'s `undici@7.29.0` → `7.29.1` (a patch — satisfies `isomorphic-dompurify`'s range). Deliberately scoped so it does **not** touch the direct `undici@8.11.2` (already safe) or the `@ai-sdk/provider-utils` → `undici@6.29.0` (outside the vulnerable `>= 7.0.0` range).
- **Remove when**: `npm audit` reports no advisories for `undici` (when `isomorphic-dompurify` ships a release pulling `undici >= 7.29.1`).

## brace-expansion (transitive, two major lines)

- **Override**: `"brace-expansion@1": "1.1.21"` and `"brace-expansion@>=2.0.0": "5.0.12"`
- **CVE**: CVE-2026-102278, CVE-2026-102276 (high, 1.x); CVE-2026-102277 (medium, 1.x and 5.x)
- **GHSA**: GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p, GHSA-q2hr-2g5m-vwhr
- **Severity**: high (plus medium)
- **Summary**: `brace-expansion` DoS via uncontrolled recursion / quadratic-time expansion; 1.x fixed in 1.1.21, 2.x+ fixed in 5.0.12
- **Dependabot alerts**: #21, #19 (high, 1.x runtime); #23 (medium, 1.x runtime); #22 (medium, 5.x dev)
- **Added**: 2026-10-02
- **Note**: Two coexisting major lines — the top-level `brace-expansion@1.1.18` (runtime, via `minimatch@3`) and `@eslint/config-array`'s `brace-expansion@5.0.9` (dev). A single global override cannot satisfy both without violating a consumer's semver range, so the override is split by major: `@1` → `1.1.21` (first release clearing all three 1.x advisories), `>=2.0.0` → `5.0.12`.
- **Remove when**: `npm audit` reports no advisories for `brace-expansion` on either line.
